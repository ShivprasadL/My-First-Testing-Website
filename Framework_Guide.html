1. 📦 pom.xml — Maven Configuration

Location: Project root   ✅ Reusable

<properties> Tag — Variables

Property Value What It Does
project.build.sourceEncoding UTF-8 Read all files as UTF-8
maven.compiler.source 17 Compile using Java 17 syntax
maven.compiler.target 17 .class files run on Java 17+
selenium.version 4.27.0 Version variable — use as ${selenium.version}
testng.version 7.10.2 Version variable for TestNG
extentreports.version 5.1.2 Version variable for ExtentReports
log4j.version 2.24.3 Version variable for Log4j
webdrivermanager.version 5.9.2 Version variable for WebDriverManager

<dependencies> Tag — External Libraries

Dependency What It Provides
selenium-java WebDriver API — controls browsers (click, type, navigate)
testng Test framework — @Test, @BeforeMethod, assertions, parallel execution
extentreports Generates beautiful HTML test reports with charts
log4j-core Log4j engine — actually writes logs to console/file
log4j-api Log4j interface — LogManager.getLogger(), logger.info()
webdrivermanager Auto-downloads correct ChromeDriver/GeckoDriver

Each dependency has 3 required parts:

<dependency>
    <groupId>org.seleniumhq.selenium</groupId>  <!-- Company -->
    <artifactId>selenium-java</artifactId>       <!-- Library name -->
    <version>${selenium.version}</version>       <!-- Version -->
    <scope>compile</scope>                       <!-- When to use -->
</dependency>

2. 📁 target/ — Compiled Output

Location: Project root   ❌ Never copy

When Maven/Eclipse compiles your .java files, the compiled .class (bytecode) files go here.

Subfolder Source Contains
target/classes/ src/main/java + resources Compiled main code + config.properties, log4j2.xml
target/test-classes/ src/test/java Compiled test code
📝 Key Points: JVM runs .class files, NOT .java files. target/ is in .gitignore — never commit it. Run mvn clean to delete and regenerate.

3. 📄 config.properties

Location: src/main/resources/   ✅ Reusable

Stores all configurable values — never hardcode in Java.

browser=chrome          # Which browser to use
headless=false          # Run without visible window?
baseUrl=https://www.facebook.com/
implicitWait=10         # Seconds to wait
explicitWait=15
screenshotOnFailure=true

Why: Change browser=firefox → entire suite runs on Firefox. No code changes!

4. 📄 log4j2.xml — Logging Config

Location: src/main/resources/   ✅ Reusable

Component What It Does
Console Appender Prints logs to Eclipse console
File Appender Writes logs to logs/automation.log (fresh each run)
com.automation Logger (DEBUG) YOUR code logs everything in detail
Root Logger (INFO) External libraries only log important stuff

Why: System.out.println() has no timestamps or levels. Log4j gives: 2026-05-15 19:30:00 [main] INFO BaseTest - Browser launched

🆕 PART 2: Newly Created Files

8. ☕ DriverFactory.java ⭐

Location: src/main/java/.../utilities/   ✅ Reusable

What: Launches Chrome/Firefox/Edge based on config. Uses ThreadLocal<WebDriver> for parallel-safe execution.

Why: Without this, you'd write 40+ lines of browser setup in EVERY test class.

DriverFactory df = new DriverFactory();
WebDriver driver = df.initDriver(prop);   // Launch browser
DriverFactory.getDriver();                // Get driver anywhere
DriverFactory.quitDriver();               // Close + prevent leak

9. ☕ WaitUtils.java ⭐

Location: src/main/java/.../utilities/   ✅ Reusable

What: Replaces Thread.sleep() with intelligent explicit waits.

❌ Thread.sleep(5000) ✅ waitForClickable(locator)
Always waits 5 seconds Waits only until element is ready
Wastes time / too short Returns immediately when ready 
WaitUtils wait = new WaitUtils(driver, 15);
wait.waitForVisible(By.id("email"));         // Wait to see
wait.waitForClickable(By.id("submit"));      // Wait to click
wait.waitForInvisible(By.className("spinner"));  // Wait to disappear
wait.waitForAlert();                         // Wait for popup

Why: #1 reason for flaky tests is improper waiting.

10. ☕ ScreenshotUtils.java

Location: src/main/java/.../utilities/   ✅ Reusable

What: Captures browser screenshot on failure. Saves as screenshots/testName_20260515_193000.png

Why: In CI/CD (no monitor), screenshots show EXACTLY what went wrong.

11. ☕ ExtentReportManager.java

Location: src/main/java/.../utilities/   ✅ Reusable

What: Generates interactive HTML report at reports/TestReport.html with pass/fail charts, system info, and failure screenshots.

ExtentReportManager.initReporter();           // @BeforeSuite
ExtentReportManager.createTest("Login Test"); // Each @Test
ExtentReportManager.getTest().pass("OK");     // Log result
ExtentReportManager.flushReporter();          // @AfterSuite

12. ☕ BaseTest.java ⭐⭐⭐ Most Important

Location: src/main/java/.../base/   ✅ Reusable

What: Parent class ALL tests extend. Handles everything automatically:

Annotation What Happens When
@BeforeSuite Initialize ExtentReports Once at start
@BeforeMethod Load config → Launch browser → Open URL Before EACH test
@AfterMethod Screenshot on failure → Close browser After EACH test
@AfterSuite Generate HTML report Once at end 
// Just extend BaseTest — everything is automatic!
public class LoginTest extends BaseTest {
    @Test
    public void testLogin() {
        // driver, prop, logger are all ready!
        driver.findElement(By.id("email")).sendKeys("test");
    }
    // Browser closes automatically after this
}

14. ☕ ExcelReader.java + @DataProvider — Parameterization ⭐

Location: src/main/java/.../utilities/   ✅ Reusable

What: Reads test data from .xlsx Excel files. Used with TestNG @DataProvider to run the same test with multiple data sets.

Flow:

Excel File (.xlsx)  →  ExcelReader  →  @DataProvider  →  @Test
┌──────────────┐   ┌─────────────┐   ┌─────────────┐   ┌──────────┐
│ email | pass │ → │getTestData()│ → │returns rows │ → │runs once │
│ user1 | 123  │   │reads Excel  │   │as Object[][]│   │per row   │
│ user2 | 456  │   │skips header │   │             │   │          │
└──────────────┘   └─────────────┘   └─────────────┘   └──────────┘

Usage in test class:

@DataProvider(name = "loginData")
public Object[][] getLoginData() {
    return ExcelReader.getTestData("src/test/resources/testdata.xlsx", "LoginData");
}

@Test(dataProvider = "loginData")
public void testLogin(String email, String password) {
    loginPage.enterEmail(email);    // "user1@test.com" (row 1)
    loginPage.enterPassword(password); // "Pass123"
    // Test runs AGAIN with row 2, row 3, etc.
}

Dependency: Apache POI (poi-ooxml 5.5.1) added to pom.xml

Why: Testers can add/edit test data in Excel without touching Java code.

15. 📄 testng.xml — Suite Runner

Location: Project root   ✅ Reusable
